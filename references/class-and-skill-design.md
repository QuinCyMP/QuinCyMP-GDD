# ออกแบบคลาส อาชีพ และสกิล

**อ่านไฟล์นี้ก่อนเขียนความสามารถใด ๆ ที่ผู้เล่นเลือกได้** — คลาส อาชีพ สาย build ทักษะ perk

---

## 0. 🔴 การวินิจฉัยที่ต้องทำก่อน — นับคำกริยา

ก่อนแก้อะไร **ให้นับคำกริยาที่ใช้บรรยายความสามารถทั้งหมด** แล้วเรียงจากมากไปน้อย

ตัวอย่างผลจริงจากร่างที่มีความสามารถ 510 ข้อ:

| คำกริยา | ครั้ง |
|---|---:|
| **ออกแบบ** | **32** |
| ทำ / สร้าง | 22 |
| **ประสาน** | **13** |
| **ตรวจ** | **8** |

> ## **นี่คือคำกริยาของที่ปรึกษา ไม่ใช่คำกริยาของเกม**

**ไม่มีคำว่า** ตี · ยิง · ผลัก · ดึง · ขว้าง · ยึด · ทลาย · ลาก **อยู่ในกลุ่มบนเลย**

ถ้าผลออกมาแบบนี้ **ปัญหาไม่ใช่ความสามารถบางข้อ แต่คือทั้งชุดเขียนผิดแนว** — ต้องรื้อ ไม่ใช่แก้ทีละข้อ

**อีกตัววัดหนึ่ง:** เอาจำนวนความสามารถหารด้วยจำนวนคลาส **ถ้าได้ประมาณ 2.0 พอดีทุกคลาส
แปลว่าคนเขียนเติมให้ครบโควตา ไม่ได้เขียนเพราะคลาสนั้นมีของจริง**

## 1. 🔴 ขั้น ⓪ — research ก่อนเสมอ ห้ามข้าม

> ## **ถ้าไม่ไปดูว่าคนอื่นทำไว้ยังไง เราจะเขียนได้แค่สิ่งที่เราเคยเล่นมา
> ## และสิ่งที่เราเคยเล่นมา คือสิ่งที่ทุกคนก็เคยเล่นมาแล้วเหมือนกัน**

### ต้องดูให้ครบสี่ช่อง — ห้ามดูแค่ช่องเดียว

| ช่อง | หาอะไรจากช่องนี้ |
|---|---|
| **MMORPG** | **โครงสร้างอาชีพและเศรษฐกิจผู้เล่น** — ใครพึ่งใคร ใครขายอะไรให้ใคร |
| **ARPG / Action RPG** | **กลไกไอเทมและค่าสถานะ** — ตีบวก ช่องรูน คุณภาพ ค่าสถานะแยกหน้าที่กันยังไง |
| **อนิเมะ / มังงะ** | **ตัวตนของอาชีพและราคาที่ต้องจ่าย** — ทำไมคนถึงกลัวหรือเคารพอาชีพนี้ |
| **นิยาย / ตำนาน** | **ที่ทางในสังคม** — อาชีพนี้อยู่ตรงไหนของโลก ไม่ใช่แค่กดสกิลอะไร |

🔴 **สองช่องแรกตอบเรื่องกลไก สองช่องหลังตอบเรื่องตัวตน** — ขาดฝั่งไหนก็ได้คลาสที่ไม่ครบ
คลาสที่มีแต่กลไกคือสเปรดชีต · คลาสที่มีแต่ตัวตนคือเรื่องสั้น

### สิ่งที่ต้องได้กลับมา — สามอย่าง

| | ได้อะไร | เอาไปทำอะไร |
|---|---|---|
| ① | **กลไกที่เกมอื่นทำแล้วเวิร์ก** | เอามาปรับ **ไม่ลอก** — และบันทึกแหล่งพร้อม ID ที่ตามกลับได้ |
| ② | ⭐ **กลไกที่เกมอื่นทำแล้ว*ไม่*เวิร์ก หรือทำไม่ได้** | **นี่คือที่ที่จุดผูกขาดมาจาก** |
| ③ | **กลไกที่ขัดกับกฎของเกมเรา** | เขียนลง "ทางเลือกที่ตัดทิ้ง" พร้อมเหตุผล — กันคนเสนอซ้ำ |

> **ข้อ ② สำคัญที่สุด** — จุดเด่นที่ดีที่สุดมักไม่ใช่ *"ทำได้ดีกว่า"*
> แต่เป็น ***"ทำได้ ในขณะที่ทั้งแนวเกมทำไม่ได้"***
>
> ตัวอย่าง: ARPG ตัวหนึ่งกำหนดว่ารูนที่ใส่แล้วถอดไม่ได้เลย →
> คลาสที่ **ถอดรูนได้** จึงเป็นของที่ทั้งแนวเกมไม่มี

### บันทึก research ยังไง

ทำไฟล์รวมแหล่งอ้างอิง แต่ละแถวต้องแยกให้ชัดสองคอลัมน์:
**"แหล่งนั้นพูดว่าอะไรจริง ๆ"** กับ **"เราตัดสินใจเอาอะไรมาใช้"**
แล้วให้ไฟล์คลาสอ้าง ID กลับมาได้ — **ไม่งั้นอีกหกเดือนจะไม่มีใครรู้ว่าทำไมถึงออกแบบแบบนี้**

## 2. เกณฑ์ห้าข้อ — ความสามารถต้องผ่านทั้งห้า

| | เกณฑ์ | คำถามที่ใช้ตรวจ |
|---|---|---|
| ① | **เป็น player verb** | ผู้เล่นทำอะไรสักอย่างไหม หรือแค่ "มีคุณสมบัติ" |
| ② | **มองเห็นได้** | คนที่ยืนดูอยู่รู้ไหมว่ามีอะไรเกิดขึ้น |
| ③ | **มีคนอื่นได้หรือเสีย** | มันแตะโลกหรือแตะผู้เล่นคนอื่นไหม |
| ④ | **มีของที่คลาสอื่นทำไม่ได้เลย** อย่างน้อยหนึ่งข้อ | ถ้าไม่มี คลาสนี้คือ reskin |
| ⑤ | **มีราคา** | ต้นทุน เวลา วัสดุ ความเสี่ยง หรือการต้องพึ่งคนอื่น |

### ตัวอย่างการตัดสินที่ใช้เป็นบรรทัดฐานได้

| ข้อเสนอ | ตัดสิน | ทำไม |
|---|---|---|
| *แยกโครงอาวุธกับโมดูลออกจากกันเพื่อบำรุง* | ✅ **ผ่าน** | **เห็นภาพได้** — อาวุธถอดออกเป็นสองชิ้นตรงหน้า |
| *ตรวจความเข้ากันก่อนประกอบ* | ❌ **ตก** | **มองไม่เห็น ไม่จำเป็น** — นี่คือ tooltip ไม่ใช่ความสามารถ |

## 3. 🔴 สิ่งที่ห้ามเป็นสกิล — เก้าข้อ

| ห้าม | เพราะ | ให้ทำอะไรแทน |
|---|---|---|
| **ตรวจ · เช็ก · ประเมิน** เฉย ๆ | เป็น UI ไม่ใช่ verb | ให้เป็นผลพลอยได้ของสกิลอื่น |
| **ออกแบบมาตรฐาน · วางระบบ** | ผู้เล่นไม่ได้ทำอะไร | เขียนเป็น**สิ่งที่ผลิตออกมา** |
| **ถ่ายทอด · ฝึกรุ่นต่อ** | ถ้ามีระบบอาจารย์–ศิษย์อยู่แล้ว **ทุกคลาสก็ใช้ได้** | ตัดทิ้ง — ไม่ใช่จุดเด่นของใคร |
| **ประสานงาน · จัดคิว** | ผู้เล่นทำในแชทอยู่แล้ว | เขียนเป็น**เครื่องมือ**ที่ทำให้การประสานเป็นไปได้ |
| **สร้างองค์กร · ตั้งสถาบัน** | ปุ่มเดียวสร้างองค์กรไม่ได้ | เขียนเป็น**สิทธิ์**ที่ปลดล็อกให้ไปทำจริง |
| **สิ่งที่ระบบแสดงให้ทุกคนเห็นอยู่แล้ว** | ถ้า UI บอกค่านั้นอยู่แล้ว สกิลนี้ไม่ได้ให้อะไร | ตัดทิ้ง |
| **ซ้ำกับสกิลอื่นในคลาสเดียวกัน** | ติดทั้งคู่แล้วผลทับกัน = เสียช่องเปล่า | รวมเป็นตัวเดียว |
| **แนวคิดของเกม ไม่ใช่ความสามารถของคลาส** | ถ้าทุกคนทำได้ตามกติกา **มันคือกติกา ไม่ใช่สกิล** | ย้ายไปไฟล์ระบบ |
| **ตัวบูสที่ทำให้เกิด "ฟลุ๊ค"** | ถ้าเกมกำหนดว่าความชำนาญพอแล้วสำเร็จแน่นอน **ไม่มีที่ให้โชคทำงาน** | เปลี่ยนเป็น**เพิ่มผลลัพธ์** ไม่ใช่เพิ่มโอกาสสำเร็จ |

⚠️ **ข้อสุดท้ายสำคัญกว่าที่คิด** — ถ้าเกมประกาศว่าไม่มีการสุ่มในระบบไหน
**ค่าสถานะที่เกี่ยวกับโชคต้องหายไปจากคลาสที่ใช้ระบบนั้นทั้งสาย** ไม่ใช่แค่จากสกิล

## 4. ⭐ สามถังที่คนสับสนกันตลอด

| | คืออะไร | โตยังไง |
|---|---|---|
| **คลังสกิล** | สิ่งที่ตัวละคร**รู้แล้ว** | โตทุกขั้น สะสมเรื่อย ๆ |
| **ช่องติดตั้ง** | สิ่งที่**ร่างกายใช้พร้อมกันได้** — รวม Passive | โตช้ากว่าคลัง |
| **แถบสกิล** | ปุ่มที่**กดได้จริงตอนสู้** — Active เท่านั้น | มักคงที่ตลอดเกม |

> ## **คลังต้องโตเร็วกว่าช่อง — ไม่งั้นไม่มีการตัดสินใจ**

**ตัวเลขอ้างอิงที่ใช้ได้:**

| ขั้น | สกิลใหม่ | คลังสะสม | ช่องติดตั้ง | ต้องทิ้ง |
|---|---:|---:|---:|---:|
| **1 เริ่มต้น** | 12–14 | ~13 | **ทั้งหมด** | **0 — ได้ทุกตัว** |
| **2** | +9–12 | ~22 | 16 | 6 |
| **3** | +8 | ~30 | 19 | 11 |
| **4** | +3–4 | ~33 | 21 | 12 |
| **5** | +3–4 | ~36 | 23 | 13 |

| ขั้น | ความรู้สึกที่ต้องการ |
|---|---|
| **1** | **"ฉันได้เรียนทุกอย่างที่อาชีพนี้ทำได้"** — ไม่มีการตัดสินใจผิดตั้งแต่ยังไม่รู้อะไร |
| **2** | ## **จุดที่ผู้เล่นสองคนคลาสเดียวกันเริ่มต่างกัน** |
| **3–5** | ของใหม่น้อยลง **แต่แต่ละตัวเปลี่ยนวิธีเล่น** ไม่ใช่ของเล็กที่กองเพิ่ม |

⚠️ **จำนวนไม่ใช่เป้าที่ต้องทำให้ครบ** — ถ้าคลาสหนึ่งมีของจริง ๆ แค่ 9 ตัว **ให้ 9 แล้วลดช่องลง**

## 5. ตารางสกิล — เจ็ดช่อง

```
| # | ชื่อสกิล | A/P | การอัพ | คำนวน | ประเภท | ทำอะไร |
```

| ช่อง | ค่าที่เป็นไปได้ |
|---|---|
| **A / P** | `A` Active กดใช้ · `P` Passive ติดตัว |
| **การอัพ** | `—` ได้แล้วคงที่ · `Lv` เก็บ EXP จากการใช้จริง · `อัพคลาส` แรงขึ้นเมื่อเลื่อนขั้น |
| **คำนวน** | `—` · `Lv` · `Lv · STR` · `× ชื่อ Stat` · `ตามขั้น` · `Stat ผู้ร่าย` · `% Stat เป้าหมาย` |
| **ประเภท** | `ตัวเอง` · `เป้าหมาย` · `Single` · `AOE` · `DoT` · `พื้นที่` · `คราฟ` |

### 🔴 คอลัมน์ **คำนวน** คือของที่คนมักลืม และมันแก้ปัญหาใหญ่

**มันไม่ได้มีไว้ใส่สูตร มันมีไว้กันการนับซ้ำ** — สกิลอ่าน Attribute ตรง ๆ
หรืออ่าน Stat ที่คำนวณแล้วก็ได้ **แต่ต้องเลือกอย่างเดียว** ไม่งั้นโบนัสถูกนับสองรอบ

🔴 **ห้ามเขียนตัวเลขจริงในคอลัมน์นี้** — `Lv · STR` พอแล้ว ไม่ต้องเขียนว่าคูณเท่าไร
ตัวเลขอยู่ในไฟล์บาลานซ์ **การใส่ตัวเลขทุกช่องทำให้ไฟล์บวมโดยไม่เพิ่มการตัดสินใจ**

**ประโยชน์ที่ได้ฟรี** — ไล่คอลัมน์นี้ลงมาทั้งขั้น **แล้วจะเห็นทันทีว่า Attribute ตัวไหนไม่มีสกิลไหนใช้เลย**

### `× ชื่อ Stat` คือรูปแบบที่สร้างการผูกขาดได้ง่ายที่สุด

**ตัวคูณทับ Stat ที่คำนวณเสร็จแล้ว** แปลว่า *"คลาสอื่นอัปค่านี้ก็ได้ผลเหมือนกัน
แต่คลาสนี้คูณทับอีกชั้น จึงเหนือกว่าทุกคนที่ลงแต้มเท่ากัน"* — เห็นภาพ วัดได้ และไม่ต้องสร้างระบบใหม่

### เขียนคำอธิบายยังไง

| ❌ | ✅ |
|---|---|
| `ฟันดาบ ทำดาเมจ 1,000 + 20% ของ STR` | **`Cleave`** — ฟันดาบทำความเสียหายแก่ศัตรู |
| `ซ่อมเกราะ +30 durability` | **`Mend`** — คืนความคงทนให้ของที่สึก |

**ระบุค่าได้เฉพาะเมื่อมันคือ*การตัดสินใจทางดีไซน์*** — *"ไม่รองรับสูงกว่าระดับ X"* · *"CD 1 สัปดาห์"*
ค่าเหล่านั้นติดป้าย `[ตัวเลขตั้งต้น]`

## 6. Attribute ของคลาส — กฎห้าข้อ

**ถ้าเกมกำหนดว่าตัวละครเริ่มต้นเท่ากันหมด บรรทัด Attribute ไม่ใช่ของแถม
มันคือคำแนะนำว่าควรลงแต้มทางไหนถึงจะใช้สกิลของคลาสนี้ได้เต็มที่**

| | กฎ | ทำไม |
|---|---|---|
| ① | **ค่าที่*สกิลใช้ทำงาน*ต้องมีสกิลอ่านจริง** — ตรวจจากคอลัมน์ `คำนวน` ของสกิลที่ขั้นนั้นเข้าถึงได้**ทั้งหมด** | ค่าที่ไม่มีสกิลไหนอ่าน คือแต้มที่ตารางบังคับให้ทิ้งเปล่า |
| ①ᵇ | 🔴 **ยกเว้นค่าเอาตัวรอด** *(HP · Stamina)* — มีประโยชน์โดยไม่ต้องมีสกิลอ่าน **แต่ต้องเขียนเหตุผลว่าขั้นนี้ถูกบังคับให้รับดาเมจตรงไหน** | ใช้กฎ ① ตรง ๆ จะตัดค่าเลือดออกจากทุกคลาส ซึ่งผิด |
| ② | **เปลี่ยนชุดค่าตามขั้นและตามกิ่งได้ และ*ควร*เปลี่ยน** | **ถ้าชุดค่าไม่เปลี่ยน การเลือกกิ่งก็ไม่มีผลต่อการลงแต้ม** |
| ③ | **สามถึงสี่ค่าพอ** | เกินสี่ค่าแปลว่าคลาสนั้นยังไม่รู้ว่าตัวเองทำอะไร |
| ④ | **ค่าที่เพิ่มเข้ามาตอนขั้นสูง ต้องบอกได้ว่าเพิ่มเพราะสกิลตัวไหน** | เขียนบรรทัดเดียวใต้ตาราง ไม่ใช่เปลี่ยนเงียบ ๆ |

> **ตัวอย่างที่ดี:** กิ่งหนึ่งเก็บค่าความอึดไว้แล้วเพิ่มค่าเลือด *(เพราะขั้นสูงบังคับให้ยืนกลางสนาม)*
> อีกกิ่งทิ้งค่าความอึดไปเอาค่าปัญญา *(เพราะสกิลกลายเป็นพลังเวท)*
> **นี่คือจุดที่ผู้เล่นสองคนคลาสเดียวกันลงแต้มคนละทางถาวร**

## 7. 🔴 เส้นแบ่งระหว่างคลาสที่ใกล้กัน

**คลาสที่ใกล้กันจะเขียนทับกันเสมอ** ถ้าไม่วางเส้นแบ่งไว้ก่อน — ตัวอย่างที่เจอจริง:
คลาสตั้งรับกับคลาสบุก **ต่างเป็นเจ้าของคำว่า "แนว" และ "สัญญาณ" พร้อมกัน 4 จุด**

### วิธีแก้ที่ได้ผล

**หาแกนที่เป็นกลไก ไม่ใช่ธีม** — *"ตั้งรับ vs บุก"* แก้ไม่ได้ เพราะทั้งคู่ยังจัดแนวเหมือนกัน

| แกนที่ใช้ได้จริง | ตัวอย่าง |
|---|---|
| **เพิ่มค่าฝั่งเรา vs ลดค่าฝั่งศัตรู** | คนหนึ่งรับแทน · อีกคนทุบเกราะ — **ผลเหมือนกัน กลไกตรงข้าม** |
| **ใครเป็นคนเลือกว่าใครจะเจ็บ** | คนหนึ่งไปหาเป้าหมาย · อีกคนถูกศัตรูเลือกเอง |
| **ดาเมจเดินทางไหม** | ไปหาคนได้ vs เกิดเฉพาะตรงที่เขายืน |
| **คุมที่ vs คุมจังหวะ** | ใครยืนตรงไหน vs เข้าเมื่อไหร่ |

### แล้วทำให้ตรวจด้วยเครื่องได้

ใส่ตารางเส้นแบ่งไว้บนหัวไฟล์**ทั้งสองฝั่ง** ข้อความเดียวกัน แล้วปิดท้ายด้วย:

```markdown
| **คำที่ห้ามใช้ในไฟล์นี้** | "รับแทน" · "บัง" | "สัญญาณ" · "สั่งการ" |
```

**แล้ว grep ตรวจได้ว่าเส้นแบ่งยังทำงานอยู่ไหม**

⭐ **ผลพลอยได้:** ถ้าเส้นแบ่งดีจริง สองคลาสจะ**แก้ทางกันเองโดยไม่ต้องออกแบบให้แก้** —
คลาสที่ลดค่าป้องกันย่อมแก้ทางคลาสที่พึ่งถังเลือด **นั่นคือหลักฐานว่าเส้นแบ่งทำงาน**

## 8. 🔁 ขั้นตอน — ทำตามลำดับนี้ทุกครั้ง

| ขั้น | ทำอะไร | ถ้าข้ามจะเกิดอะไร |
|---|---|---|
| **⓪** | 🔴 **research ครบสี่ช่อง** *(หัวข้อ 1)* | ได้คลาสที่เหมือนเกมที่เคยเล่น และไม่มีสกิลไหนที่คนจำได้ว่ามาจากเกมนี้ |
| **①** | **ถามก่อนว่าระบบของเกมมีอะไรและไม่มีอะไร** | เขียนสกิลอ้างระบบที่ไม่มีอยู่ แล้วต้องรื้อทั้งไฟล์ |
| **②** | **หา "สิ่งที่คลาสนี้ผูกขาด"** อย่างน้อยกิ่งละหนึ่ง | ได้คลาสที่ทำได้หลายอย่างแต่ไม่มีอะไรจำเป็น |
| **③** | **เขียนจุดเด่นข้อเดียวของทุกโหนดก่อนเขียนสกิล** | สกิลจะกองรวมกันโดยไม่มีทิศ |
| **④** | **วางเส้นแบ่งกับคลาสที่ใกล้กัน** *(หัวข้อ 7)* | สองไฟล์จะเขียนคำเดียวกันโดยไม่มีใครรู้ |
| **⑤** | เขียนขั้นแรกให้ครบ **แล้วค่อยแตกกิ่ง** | กิ่งจะมีสกิลซ้ำกันเอง |
| **⑥** | เขียนขั้นสองให้**มากกว่าช่องติดตั้ง** | ทุกคนที่เล่นคลาสนี้เหมือนกันหมด |
| **⑦** | ขั้นสูง **ของน้อยแต่เปลี่ยนวิธีเล่น** + ระบุสกิลเดิมที่แรงขึ้น | ขั้นสูงกลายเป็นตัวเลขที่โตขึ้นเฉย ๆ |
| **⑧** | **ไล่ตัดด้วยข้อห้ามเก้าข้อ** แล้วค่อยนับจำนวน | ได้สกิลครบโควตาแต่ครึ่งหนึ่งไม่มีความหมาย |
| **⑨** | **ปรับช่องติดตั้งตามจำนวนที่เหลือจริง** | ไฟล์บวมโดยไม่ได้เพิ่มการตัดสินใจ |

### คำถามที่ต้องถามเจ้าของก่อนเริ่มทุกคลาส

1. **คลาสนี้ผูกขาดอะไร** — ฟังก์ชันไหนที่ไม่มีใครทำแทนได้
2. **มีระบบอะไรที่คลาสนี้พึ่งอยู่ แต่ยังไม่ได้เขียนลงเอกสาร**
3. **ควรมีกี่กิ่ง** — 🔴 **ตัดสินทีละคลาส ไม่ตัดสินล่วงหน้า** และ**ตัดสินหลังเขียนจุดเด่นครบทุกโหนดแล้ว**

## 9. เกณฑ์ตรวจก่อนปิดงานแต่ละคลาส

| | ตรวจอะไร |
|---|---|
| 1 | ทุกสกิลผ่าน**เกณฑ์ห้าข้อ** |
| 2 | ไม่เหลือสิ่งที่ห้ามใน**ข้อห้ามเก้าข้อ** |
| 3 | ทุกโหนดมี**จุดเด่นข้อเดียว** และไม่ซ้ำกับโหนดอื่นในคลาสเดียวกัน |
| 4 | 🔴 **ทุกกิ่งมีสกิลผูกขาดอย่างน้อยหนึ่งตัว** |
| 5 | ทุกสกิลมีครบ **7 ช่อง** |
| 6 | ขั้นสูงมีทั้ง **สกิลใหม่** และ **สกิลเดิมที่แรงขึ้นอย่างน้อย 2 ตัว** *(เขียนให้เห็นภาพ ไม่ใช่ +%)* |
| 7 | สัดส่วน Active/Passive **เข้ากับที่คลาสนี้ทำงานจริง** — งานที่โต๊ะควร Passive เป็นหลัก |
| 8 | ตัวเลขทุกตัวติดป้าย `[ตัวเลขตั้งต้น]` |
| 9 | **อ่านจุดเด่นของสองกิ่งติดกัน แล้วบอกได้ว่าจะเลือกอันไหนโดยไม่ต้องดูตัวเลข** |
| 10 | 🔴 **ทุกค่าในบรรทัด Attribute มีสกิลอ่านจริง** *(ยกเว้นค่าเอาตัวรอด — ต้องมีเหตุผลเขียนไว้)* |
| 11 | **มีแหล่ง research อ้างถึงอย่างน้อยหนึ่งรายการ** และครบสี่ช่อง |
| 12 | มีหัวข้อ **ทางเลือกที่ตัดทิ้ง** พร้อมเหตุผล รวมของที่ตัดจาก research |
| 13 | 🔴 **ตรวจคำต้องห้ามของเส้นแบ่ง** ว่าไม่หลุดเข้ามาในเนื้อสกิล |
| 14 | อัปเดตดัชนี · แผนผัง · frontmatter ถ้าจำนวนโหนดเปลี่ยน |

## 10. เก็บมาตรฐานนี้ไว้ในโปรเจกต์ด้วย

**เมื่อทำคลาสแรกจบ ให้ทำไฟล์มาตรฐานไว้ในโปรเจกต์เอง** พร้อมระบุว่าคลาสไหนคือ**ไฟล์อ้างอิง**
เพราะกฎที่ปรับตามเกมนั้นแล้วมีค่ากว่ากฎทั่วไป — และคลาสที่เหลืออีกหลายสิบตัวจะได้หน้าตาเหมือนกัน

⚠️ **และเมื่อรันกฎกับไฟล์จริงแล้วมันยิงพลาด ให้แก้กฎ ไม่ใช่บิดไฟล์ให้เข้ากฎ**

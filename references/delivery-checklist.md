# Delivery checklist

Copy the checkboxes below into a pull request or review before handing over design documents.
The authoritative wording is in [SKILL.md, Delivery checklist](../SKILL.md#delivery-checklist).
Change definitions there first, then refresh this mirror.

- [ ] **Stranger test.** Someone who never spoke to the user reads the one-pager (`00-one-pager.md` in the standard layout) and can explain the game to a friend correctly.
- [ ] **Programmer test.** There are enough numbers to start coding at least one system without asking a question.
- [ ] **Distinctiveness test.** With the title removed, a reader can still tell this apart from a generic MMO.
- [ ] **Rejection test.** Every file has a real "Alternatives considered and rejected" section with reasons.
- [ ] **Honesty test.** Every unknown is marked `[UNDECIDED: ...]` or `[PROVISIONAL: ...]`, not covered with prose.
- [ ] **Contradiction test** (Phase B). Nothing just written makes a sentence in an older file false. If it does, fix the source, never leave two files disagreeing.
- [ ] **Single-home test** (Phase B). The rule just written does not already exist elsewhere; if it does, one home was chosen and the rest link to it.

Tests 6 and 7 apply to Phase B.
Fix failed checks before reporting the document done.

The checkbox format follows [GitHub’s tasklist documentation](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/about-tasklists).
